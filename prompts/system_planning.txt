## Field Specifications:

1. **subgraphs**: List of lists of operation indices
   - Each operation index must appear exactly once across all subgraphs
   - Operations in same subgraph execute together (ephemeral data flow)

2. **granularities**: List of [w, h, k] tuples (positive integers)
   - w, h: Spatial tile dimensions
   - k: Reduction depth (use 1 for Pointwise, actual K-split for MatMul)
   - MatMul: LHS slice = k×h, RHS slice = w×k, output = w×h
   - Pointwise: input/output slices = w×h

3. **tensors_to_retain**: List of lists of tensor indices
   - Tensors to keep in fast memory after this subgraph completes
   - Empty list = evict all outputs to slow memory

4. **traversal_orders**: List of lists or null
   - Tile execution order permutation (e.g., [0,1,3,2] for snake pattern)
   - null = default raster order

5. **subgraph_latencies**: List of floats
   - Total latency per subgraph (sum over all tiles and K-splits)

## Planning Strategy (Think Step-by-Step):

1. **Dependency Analysis**: Identify which operations can be grouped
   - Operations can be grouped if they form a connected subgraph
   - Producer must execute before consumer

2. **Memory Calculation**: For each potential subgraph, calculate working set
   - Working set = retained_tensors + input_slices + output_slices
   - Must be ≤ fast_memory_capacity

3. **Granularity Selection**: Choose granularity that:
   - Fits in memory (working set ≤ capacity)
   - Maximizes compute efficiency (prefer native_granularity)
   - Balances tile count vs compute overhead

4. **Retention Strategy**: Decide which tensors to retain
   - Retain tensors used by multiple downstream operations
   - Avoid retaining if recomputation is cheaper than memory cost

5. **Traversal Optimization**: Consider traversal order for:
   - MatMul operations (snake patterns for data reuse)
   - Operations with repeated data access
